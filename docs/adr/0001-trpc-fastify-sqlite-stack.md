# tRPC на Fastify + SQLite/Drizzle для бэкенда

Фронт (`app/`) уже целиком на TypeScript и TanStack Query, а мок-слой в `app/src/lib/api/hooks.ts` спроектирован так, чтобы заменить только `queryFn`/`mutationFn`. Взяли **tRPC поверх Fastify** — типы шарятся между клиентом и сервером напрямую, без ручного поддержания DTO и без отдельного слоя кодогенерации (как было бы с GraphQL/REST+OpenAPI).

Хранилище — **SQLite через Drizzle**, а не Postgres, вопреки более ранней (ещё не подтверждённой пользователем) идее «когда-нибудь Postgres» из более раннего обсуждения проекта. Нагрузка — 1-2 одновременных редактора, весь альянс; отдельная управляемая СУБД не оправдана этим масштабом, а один файл SQLite сильно упрощает и разработку, и (потенциально бесплатный/дешёвый) деплой.

Оба выбора считаем осознанным компромиссом ради масштаба проекта, а не default'ом «просто взяли что попроще» — если нагрузка/число редакторов вырастет на порядки, это первое, что стоит пересмотреть.
