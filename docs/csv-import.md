# Импорт CSV

Как заливаются два read-only «снапшот»-ресурса (см. [`docs/database.md`](./database.md) и `CONTEXT.md` → «Импортируемые данные»): `elixir-race`, `contribution`. Реализация — `server/src/routes/importCsv.ts`, этот файл может отставать от кода при расхождении.

Ни один из этих ресурсов не редактируется через UI приложения — только заливкой файла офицером.

`player-stats` и `weekly-rating` как ресурсы импорта больше не существуют: дуэльная/силовая статистика профиля теперь вычисляется (см. `docs/database.md` → «Вычисляемые метрики профиля»), а бывший `weekly-rating` слился с `contribution` — это была одна и та же сущность («Вклад», см. CONTEXT.md, ADR 0003) под двумя разными именами. `formation` тоже больше не ресурс импорта — «Формация» теперь читает координаты живьём из `players.coords_x/y`, которые редактирует офицер во вкладке «Игроки» (см. ADR 0007).

## Эндпоинт

```
POST /api/import/:resource
```

Обычный Fastify-роут, **не tRPC** — нужен был multipart file upload, ради которого не хотелось тащить это в tRPC-роутеры.

- **Авторизация**: та же cookie-сессия (`remedium_session`), что и у остального API. Требуется `canEdit = true` у аккаунта.
  - Нет сессии → `401 {"error": "Не авторизован."}`
  - Есть сессия, но `canEdit: false` → `403 {"error": "Требуется право редактирования."}`
- **`:resource`** — один из `elixir-race` | `contribution`. Любое другое значение (включая старые `player-stats`/`weekly-rating`/`formation`) → `404`.
- **Тело запроса** — `multipart/form-data`:
  - поле `file` — сам CSV;
  - для `contribution` дополнительно обязательное поле формы `weekStart` (дата начала недели, `YYYY-MM-DD`, естественный ключ накопления).

## Как обрабатывается запрос

1. CSV парсится (`csv-parse`, `columns: true`) — **первая строка файла обязана быть заголовком** с именами колонок, совпадающими с именами полей ниже (регистр важен).
2. **Каждая строка** валидируется через zod-схему конкретного ресурса, все строки разом (`z.array(rowSchema).safeParse(...)`).
3. Если хотя бы одна строка не прошла — **ничего не пишется в БД**, ответ `400`:
   ```json
   { "error": "Файл не прошёл проверку.", "issues": [ /* zod issues: путь до поля + что не так */ ] }
   ```
   Существующие данные в таблице в этом случае не трогаются — запись начинается только после того, как весь файл прошёл валидацию целиком.
4. Если файл валиден — запись в БД (см. «Замена vs накопление» ниже).
5. Успех: `200 {"ok": true, "imported": <кол-во строк>}`.

## Формат CSV по ресурсам

### `elixir-race`

| Колонка | Тип/формат | Допустимые значения |
|---|---|---|
| `nick` | строка, непустая | |
| `level` | число | |
| `team` | строка | `Основа А`, `Основа Б`, `Резерв А`, `Резерв Б`, `Не зарегистрирован` |
| `participation` | строка | `Да`, `Нет`, `Не знает` |

```csv
nick,level,team,participation
Ironclad,30,Основа А,Да
Atobar,25,Резерв А,Да
```

### `contribution` — «Вклад»

CSV содержит только `nick`+`points`; к какой неделе они относятся — задаётся полем формы `weekStart`, не колонкой файла (тот же способ, каким раньше заливался `weekly-rating`).

| Колонка | Тип/формат |
|---|---|
| `nick` | строка, непустая |
| `points` | число |

```csv
nick,points
Ironclad,5820
Atobar,3120
```

Колонка `group` больше не читается (группа — живой атрибут игрока, не факт про неделю, см. `docs/database.md`).

## Замена vs накопление

- **`elixir-race`** — каждый импорт **удаляет всю таблицу и вставляет заново**. Это снапшот на момент сверки, истории не хранится.
- **`contribution`** — устроен иначе, копится по неделям:
  1. Удаляются только строки `contribution_entries` с этим `weekStart`.
  2. Вставляются новые строки для этой недели.

  То есть повторная заливка с тем же `weekStart` **перезаписывает только эту неделю**, остальные недели не трогаются. На чтении: «Рейтинг игроков» (`contribution.history`) берёт последние 5 записанных недель, «Анализ вклада» (`contribution.list`) — только самую свежую.

## Примеры запросов

```bash
# сессия уже получена через auth.login, cookie в cookies.txt

curl -b cookies.txt -F "file=@elixir-race.csv" \
  http://<host>/api/import/elixir-race

curl -b cookies.txt -F "file=@contribution_2026-09-13.csv" -F "weekStart=2026-09-13" \
  http://<host>/api/import/contribution
```

## На заметку

- Имена колонок в CSV должны **точно** совпадать с именами полей в таблицах выше — лишние колонки в файле игнорируются, а вот отсутствующая обязательная колонка провалит валидацию всего файла.
- Пустой CSV (только заголовок, без строк) — валиден, просто очистит таблицу (или неделю) без вставки новых строк.
