# Импорт CSV

Как заливаются пять read-only «снапшот»-таблиц (см. [`docs/database.md`](./database.md) и `CONTEXT.md` → «Импортируемые данные»): `elixir-race`, `formation`, `contribution`, `player-stats`, `weekly-rating`. Реализация — `server/src/routes/importCsv.ts`, этот файл может отставать от кода при расхождении.

Ни один из этих пяти ресурсов не редактируется через UI приложения — только заливкой файла офицером.

## Эндпоинт

```
POST /api/import/:resource
```

Обычный Fastify-роут, **не tRPC** — нужен был multipart file upload, ради которого не хотелось тащить это в tRPC-роутеры.

- **Авторизация**: та же cookie-сессия (`remedium_session`), что и у остального API. Требуется `canEdit = true` у аккаунта.
  - Нет сессии → `401 {"error": "Не авторизован."}`
  - Есть сессия, но `canEdit: false` → `403 {"error": "Требуется право редактирования."}`
- **`:resource`** — один из `elixir-race` | `formation` | `contribution` | `player-stats` | `weekly-rating`. Любое другое значение → `404`.
- **Тело запроса** — `multipart/form-data`:
  - поле `file` — сам CSV;
  - для `weekly-rating` дополнительно обязательное поле `weekStart` (дата начала недели, естественный ключ) и необязательное `label` (подпись недели, по умолчанию = `weekStart`).

## Как обрабатывается запрос

1. CSV парсится (`csv-parse`, `columns: true`) — **первая строка файла обязана быть заголовком** с именами колонок, совпадающими с именами полей ниже (регистр важен).
2. **Каждая строка** валидируется через zod-схему конкретного ресурса, все строки разом (`z.array(rowSchema).safeParse(...)`).
3. Если хотя бы одна строка не прошла — **ничего не пишется в БД**, ответ `400`:
   ```json
   { "error": "Файл не прошёл проверку.", "issues": [ /* zod issues: путь до поля + что не так */ ] }
   ```
   Существующие данные в таблице в этом случае не трогаются — запись начинается только после того, как весь файл прошёл валидацию целиком.
4. Если файл валиден — запись в БД (см. «Замена vs накопление» ниже).
5. Успех: `200 {"ok": true, "imported": <кол-во строк>}`.

## Формат CSV по ресурсам

### `elixir-race`

| Колонка | Тип/формат | Допустимые значения |
|---|---|---|
| `nick` | строка, непустая | |
| `level` | число | |
| `team` | строка | `Основа А`, `Основа Б`, `Резерв А`, `Резерв Б`, `Не зарегистрирован` |
| `participation` | строка | `Да`, `Нет`, `Не знает` |

```csv
nick,level,team,participation
Ironclad,30,Основа А,Да
Atobar,25,Резерв А,Да
```

### `formation`

| Колонка | Тип/формат | Допустимые значения |
|---|---|---|
| `x`, `y` | число | координаты тайла на карте |
| `nick` | строка, непустая | |
| `power` | число или пусто | пустая ячейка → `null` (не удалось разобрать со скриншота) |
| `role` | строка | `attacker`, `mixed`, `defender`, `none` |

```csv
x,y,nick,power,role
680,428,Зет~Ангел,33,attacker
684,428,Гаечка7777,,attacker
```

### `contribution`

| Колонка | Тип/формат | Допустимые значения |
|---|---|---|
| `nick` | строка, непустая | |
| `group` | строка | `R1`, `R2`, `R3`, `R4`, `R5` |
| `points` | число | |

```csv
nick,group,points
Axxxiles,R4,53664201
```

### `player-stats`

| Колонка | Тип/формат |
|---|---|
| `nick` | строка, непустая |
| `avgDuelScore` | число |
| `avgDuelRank` | число |
| `strongerThanPercent` | число |
| `weeklyPowerChangePercent` | число (дробное, допускается) |

```csv
nick,avgDuelScore,avgDuelRank,strongerThanPercent,weeklyPowerChangePercent
Atobar,18420,11,80,4.2
```

### `weekly-rating`

CSV содержит только `nick`+`points`, к какой неделе они относятся — задаётся полем формы `weekStart`, не колонкой файла.

| Колонка | Тип/формат |
|---|---|
| `nick` | строка, непустая |
| `points` | число |

```csv
nick,points
Ironclad,5820
Atobar,3120
```

## Замена vs накопление

- **`elixir-race`, `formation`, `contribution`, `player-stats`** — каждый импорт **удаляет всю таблицу и вставляет заново**. Это снапшот на момент сверки, истории не хранится.
- **`weekly-rating`** — устроен иначе, копится по неделям:
  1. Ищется строка `rating_weeks` с `weekStart` из запроса; если её нет — создаётся (с `label`).
  2. Удаляются только строки `weekly_rating_entries`, принадлежащие этой неделе (`weekId`).
  3. Вставляются новые строки для этой недели.

  То есть повторная заливка с тем же `weekStart` **перезаписывает только эту неделю**, остальные недели не трогаются. На чтении (`weeklyRating.list`) берутся последние 5 записанных недель.

## Примеры запросов

```bash
# сессия уже получена через auth.login, cookie в cookies.txt

curl -b cookies.txt -F "file=@contribution.csv" \
  http://<host>/api/import/contribution

curl -b cookies.txt -F "file=@rating_2026-09-13.csv" -F "weekStart=2026-09-13" \
  http://<host>/api/import/weekly-rating
```

## На заметку

- Схема `player-stats` не обсуждалась явно с пользователем при проектировании — добавлена по аналогии с остальными снапшотами (см. `CONTEXT.md`).
- Имена колонок в CSV должны **точно** совпадать с именами полей в таблицах выше — лишние колонки в файле игнорируются, а вот отсутствующая обязательная колонка провалит валидацию всего файла.
- Пустой CSV (только заголовок, без строк) — валиден, просто очистит таблицу (или неделю) без вставки новых строк.
